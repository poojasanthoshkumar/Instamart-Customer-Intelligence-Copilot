# Instamart Customer Intelligence & Support Copilot

## Project Overview

This project builds a reproducible data foundation for customer intelligence and support automation using Python, pandas, and SQLite. Part A focuses on raw-data auditing, data cleaning, database construction, SQL analysis, and exploratory data analysis (EDA).

## Technology Stack

- Python 3.11 or later
- pandas and NumPy
- SQLite 3.25 or later
- scikit-learn and joblib
- VS Code and Git

## Setup and Reproduction

1. Install Python 3.11 or later and Git.
2. Clone the repository and navigate to the project directory.
3. Create and activate a virtual environment.

   **Windows PowerShell:**

   ```powershell
   python -m venv .venv
   .\.venv\Scripts\Activate.ps1
   ```

4. Install the project dependencies.

   ```powershell
   python -m pip install -r requirements.txt
   ```

5. Generate the raw datasets.

   ```powershell
   python generate_data.py
   ```

6. Audit the raw data.

   ```powershell
   python audit_data.py
   ```

7. Clean the datasets.

   ```powershell
   python clean_customers.py
   python clean_products.py
   python clean_orders.py
   ```

8. Build the SQLite database.

   ```powershell
   python build_database.py
   ```

9. Validate the cleaned datasets and database.

   ```powershell
   python validate_database.py
   ```

   The expected successful completion message is `ALL CHECKPOINTS PASSED`.

10. Execute the seven SQL analyses.

    ```powershell
    python run_sql_queries.py
    ```

    The expected successful completion message is `ALL SEVEN SQL QUERIES EXECUTED SUCCESSFULLY`.

11. Run the pandas analysis.

    ```powershell
    python pandas_analysis.py
    ```

    The expected successful completion message is `ALL PANDAS ANALYSIS CHECKS PASSED`.

## Data Cleaning Rules

### Customers

- Standardized city names by trimming whitespace and applying title case.
- Standardized gender values to `male`, `female`, or `unknown`.
- Treated ages outside the 10 to 100 range as invalid and set them to missing.
- Imputed missing ages using the median age within each city.
- Converted signup dates to datetime format.

### Products

- Retained the 40 product records and verified product ID uniqueness.
- Checked for missing values and standardized category data where required.

### Orders

- Converted order timestamps to datetime.
- Removed 119 exact duplicate records and retained the latest record for each order ID, producing 12,309 unique orders.
- Converted order amounts to numeric values and treated invalid amounts as missing.
- Replaced missing order amounts using product price, quantity, and discount:

  price_inr * quantity * (1 - discount_pct / 100)
- Treated negative delivery times as missing.
- Imputed missing delivery times for completed orders using the median for the corresponding product category.
- Kept delivery times missing for cancelled orders.

## Database Design

The SQLite database, `data/instamart.db`, contains three tables:

- `customers`
- `products`
- `orders`

The database is built from the cleaned CSV files. Order timestamps are stored as text in `YYYY-MM-DD HH:MM:SS` format.

The seven SQL queries cover customer spending, city and category revenue, above-average product prices, customers without completed orders, spending relative to the customer average, city-wise customer rankings, and cumulative daily revenue.

## Reproducibility and Integrity

The supplied `generate_data.py` and `mock_llm.py` files are retained unchanged. The raw datasets are generated by the supplied data generator, while cleaning scripts create the cleaned CSV files and SQLite database. Validation scripts check key row counts, missing-value rules, revenue totals, database tables, and query outputs.
