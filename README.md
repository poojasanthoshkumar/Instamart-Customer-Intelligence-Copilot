## Data Cleaning Rules

### Customers

- Standardized city names by trimming whitespace and applying title case.
- Standardized gender values to `male`, `female`, or `unknown`.
- Treated ages outside the 10 to 100 range as invalid and set them to missing.
- Imputed missing ages using the median age within each city.
- Converted signup dates to datetime format.

### Products

- Retained the 40 product records and verified product ID uniqueness.
- Checked for missing values and standardized category data where required.

### Orders

- Converted order timestamps to datetime.
- Removed 119 exact duplicate records and retained the latest record for each order ID, producing 12,309 unique orders.
- Converted order amounts to numeric values and treated invalid amounts as missing.
- Replaced missing order amounts using product price, quantity, and discount:

  price_inr * quantity * (1 - discount_pct / 100)
- Treated negative delivery times as missing.
- Imputed missing delivery times for completed orders using the median for the corresponding product category.
- Kept delivery times missing for cancelled orders.

## Database Design

The SQLite database, `data/instamart.db`, contains three tables:

- `customers`
- `products`
- `orders`

The database is built from the cleaned CSV files. Order timestamps are stored as text in `YYYY-MM-DD HH:MM:SS` format.

## Part B: Customer Intelligence

### 1. RFM Analysis

RFM analysis was performed using completed orders as of the snapshot date `2025-10-01 00:00:00`.

- **Recency:** Number of days since the customer's most recent completed order.
- **Frequency:** Number of distinct completed orders.
- **Monetary:** Total amount spent across completed orders.

The resulting RFM dataset contains 1,175 customers.

| Metric | Result |
|---|---:|
| Customers analysed | 1,175 |
| Median recency | 19 days |
| Minimum recency | 0 days |
| Maximum recency | 180 days |
| Mean frequency | 9.46 orders |
| Maximum frequency | 33 orders |
| Mean monetary value | INR 2,552.06 |
| Maximum monetary value | INR 14,766.55 |

Output: `outputs/rfm_table.csv`

### 2. Customer Segmentation

RFM features were standardised using `StandardScaler`. K-Means clustering was evaluated for K values from 2 to 8 using `n_init=10` and `random_state=42`. Silhouette scores and inertia were recorded, and K=4 was selected.

The four segments were profiled using their mean recency, frequency, and monetary values. The segment with the highest mean monetary value was labelled Premium.

| Segment | Customers | Mean Recency (days) | Mean Frequency | Mean Monetary (INR) |
|---|---:|---:|---:|---:|
| At-Risk Customers | 436 | 28.86 | 3.77 | 1,057.62 |
| Premium | 138 | 24.12 | 6.77 | 7,129.70 |
| Loyal Customers | 419 | 8.77 | 19.40 | 3,410.02 |
| Dormant Customers | 182 | 109.04 | 2.20 | 685.99 |

The first two PCA components explain 85.2% of the variance in the standardised RFM data.

Outputs:
- `outputs/kmeans_evaluation.csv`
- `outputs/rfm_scaled.csv`
- `outputs/customer_segments.csv`
- `outputs/segment_profiles.csv`

### 3. Lapse Prediction

The lapse cohort included customers with at least one completed order before `2025-09-01`. A customer was labelled as lapsed if they had no completed order between `2025-09-01` and `2025-09-30`.

The dataset contains 1,156 customers, including 443 lapsed customers (38.32%). A stratified train-test split was used with `test_size=0.20` and `random_state=42`.

Features included historical recency, frequency, monetary value, average discount, cancellation rate, average delivery time, favourite product category, city, age, gender, and customer tenure. Features were derived only from information available before the lapse cutoff. Preprocessing was fitted on the training data to avoid data leakage.

Logistic Regression and Random Forest were evaluated using five-fold cross-validation with F1 scoring.

| Model | Best Parameters | CV F1 | Test Precision | Test Recall | Test F1 |
|---|---|---:|---:|---:|---:|
| Logistic Regression | C = 0.1 | 0.6469 | 0.6180 | 0.6180 | 0.6180 |
| Random Forest | max_depth = 8, min_samples_leaf = 5 | 0.6812 | 0.6000 | 0.6404 | 0.6196 |

The always-not-lapsed baseline achieved an accuracy of approximately 61.6% but an F1 score of 0 for the lapsed class. The trained models therefore provide useful identification of customers at risk of lapsing beyond the baseline strategy.

Outputs:
- `outputs/lapse_dataset.csv`
- `outputs/lapse_model_comparison.json`
- `outputs/lapse_model.joblib`

### 4. Oversampling and Model Interpretation

Random oversampling with replacement was applied to the training data only. The test set remained unchanged. The Logistic Regression model was refitted on the balanced training data and evaluated on the same test set.

| Logistic Regression | Precision | Recall | F1 |
|---|---:|---:|---:|
| Original training distribution | 0.6180 | 0.6180 | 0.6180 |
| Oversampled training distribution | 0.5738 | 0.7865 | 0.6635 |

Oversampling increased recall and F1, while precision decreased. This trade-off can help identify more potentially lapsed customers but may also increase unnecessary retention outreach.

Random Forest feature importances and Logistic Regression coefficients were exported to support model interpretation.

Outputs:
- `outputs/logistic_oversampling_comparison.csv`
- `outputs/logistic_oversampling_details.json`
- `outputs/lapse_logistic_oversampled.joblib`
- `outputs/random_forest_feature_importance.csv`
- `outputs/logistic_regression_coefficients.csv`

### 5. Retention List and Reproducibility

A retention list was generated by ranking Premium-segment test customers by predicted lapse probability. Two of the ten customers in the exported list were labelled as lapsed.

Output: `outputs/retention_list.csv`

Saved models were reloaded and their predictions compared with the original predictions to verify reproducibility.

**Interpretation limitation:** Premium membership is assigned using the full RFM snapshot, whereas lapse prediction uses a historical cutoff. Consequently, the Premium-filtered retention list is an illustrative prioritisation output rather than a fully leakage-free estimate of prospective retention performance.
